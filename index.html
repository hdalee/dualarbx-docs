Read first

使用前必讀

!
策略面板的「▶ 開始」會送出真實訂單。

先以最小數量測試，確認交易方向、交易對、倍率、槓桿模式與兩邊實際成交量。任何單邊成交都會形成未對沖曝險。

⚠
重要風險提示

使用 API 下單可能因網路問題、交易所系統故障、行情劇烈波動或未知程式錯誤而產生損失。本系統無法保證在所有情況下正常運行；使用者應自行評估風險，並對交易決策與結果負責。使用前請確實了解加密貨幣交易風險，並依自身風險承受能力操作。

!
OKX 極端行情可能延遲成交，且 API 不一定回傳失敗。

「沒有錯誤」不代表訂單已立即成交。遇到劇烈波動、兩邊倉位不一致或價格停止更新時，請立即手動停止策略，直接到 OKX 查詢原訂單狀態、未成交委託、成交紀錄與倉位；在確認原訂單不會繼續成交前，不要補單或重新啟動策略，以免原訂單延遲成交後形成重複部位。

  • API Key 只開啟查詢與交易權限；除非另有必要，請勿開啟提幣權限。
  • 若交易所支援 IP 白名單，請限制為執行 DualArbX 的固定 IP。
  • 先在交易所端確認保證金模式、槓桿、最小下單量與可用餘額。
  • 自動下單期間保持程式、網路與電腦持續運作，不要讓電腦休眠。
  • 下單失敗或逾時時，立即到兩個交易所核對實際成交與倉位。
⚠
兩種「開始」用途不同。

交易對資訊 → 開始只建立行情連線；策略 → ▶ 開始才會啟用自動下單。

7 steps

快速開始

  1. 設定授權與憑證

    開啟「功能 → 系統設定」，從介面填入授權序號與交易所 API 後儲存。

  2. 選擇交易所

    在交易所 1、2 下拉選單選擇合約或現貨，並檢查畫面顯示的 API 名稱。

  3. 設定下單模式

    按各交易所旁的 ⚙，確認「槓桿下單」與「減倉 Only」。

  4. 輸入標的

    填寫交易對 1、2 與加乘比例；一般相同商品的倍率維持 1。

  5. 連接行情

    按交易對資訊區的「開始」，等待兩個交易所均顯示連接成功。

  6. 核對資訊

    確認價格持續更新，並用「倉位」查看兩邊現有部位與方向。

  7. 啟動策略

    填妥策略參數，按「▶ 開始」，再次核對確認視窗後才同意下單。

Setup

啟動與初始設定

下載對應的發行包

使用者直接下載 dist 內符合電腦平台的壓縮檔即可，不需要安裝 Maven、Java 或自行建置。請完整解壓縮，不要只取出啟動腳本。

依作業系統啟動
平台下載檔案啟動腳本
macOS Apple SiliconMacArm.zipTerminal 執行 ./launcher
macOS IntelMacX64.zipTerminal 執行 ./launcher
Windows x64WinX64.zip執行 launcher.bat

macOS：排除安全性警告並啟動

macOS 會對從網路下載的壓縮檔加上隔離標記。確認檔案來自可信任的發行來源後，在 Terminal 進入解壓縮後的資料夾，執行：

cd "/解壓縮後的/DualArbX資料夾" xattr -dr com.apple.quarantine . chmod +x launcher ./launcher

程式執行期間請保留 Terminal 視窗。日後再次啟動時，只要進入相同資料夾執行 ./launcher，不必重複排除隔離標記。

Windows：直接啟動

完整解壓縮 WinX64.zip 後，執行資料夾內的 launcher.bat。不要把批次檔單獨移出，否則會找不到內附的 JRE 與 CPTools.jar。

第一次設定授權與 API

  1. 啟動程式後，開啟 功能 → 系統設定。
  2. 在「系統」頁填入授權序號，並視需要切換深色主題。
  3. 切到交易所分頁，填入 name（畫面辨識名稱）、apiKey、secretKey，以及該交易所要求的 password / passphrase。
  4. Hyper、Aster 等特殊帳號依欄位提示填入錢包位址、私鑰或簽章模式。
  5. 按「儲存」。已連線的交易所需重新啟動後才會套用新設定。
i
請從設定介面管理憑證

系統會把設定保存到本機。日常新增或修改授權與 API 時，請使用「功能 → 系統設定」，不需要手動編輯設定檔。

How it works

系統運作方式

畫面更新較慢，不代表下單偵測較慢

畫面固定每 500 毫秒批次更新一次，最高約每秒 2 次，以降低繪圖與電腦效能需求。這個限制只套用在畫面顯示。

實際策略會在收到任一交易所的掛單簿更新時，立即重新計算價差與深度並檢查下單條件；反應速度仍會受到網路、交易所行情推送與 API 回應時間影響。

  1. 收到掛單簿變動

    WebSocket 更新任一交易所的最新價格與數量。

  2. 重算價差與深度

    依策略方向、加乘比例與最多前 5 檔深度重新計算。

  3. 檢查所有條件

    確認價差、掛單簿最低、下單間隔與次數上限。

  4. 兩邊同時送單

    符合條件時，並行送出交易所 1 與交易所 2 的訂單。

  5. 核對兩邊結果

    兩邊成功才累計一次；任一邊失敗或逾時就停止策略並查倉。

⚠
失敗即停止：最多裸奔一單，不會一直累加。

當任一邊 API 明確回傳失敗時，系統會立即停止策略，不再送出後續訂單；若另一邊已成功，最多只會留下當次一單未對沖。收到錯誤後仍須人工核對兩邊訂單與倉位。OKX 未回傳失敗的延遲成交屬於另一種風險，請依前述 OKX 警告處理。

即使下單金額很小，也不建議在無人監控的情況下長時間或過夜執行。

Exchange

選擇交易所與下單設定

  1. 在「1」選擇第一個交易所，在「2」選擇第二個交易所。
  2. 確認兩邊不是「請選擇」，且 API 名稱是預期帳號。
  3. 按各站點右側的 ⚙ 開啟該站點下單設定。

選項用途使用時機

Market data

輸入交易對並連接行情

交易對與加乘

欄位填寫方式範例
交易對1／2填各交易所實際使用的商品代碼。若只填基礎幣，程式會自動補上 USDT。BTC → BTCUSDT；也可直接填 ETHUSDC 或含 PERP 的代碼。
加乘1／2價格比較時的比例校正，必須大於 0。同一商品通常都填 1。標的有倍數、反向或單位差時，依實際合約關係校正。

價差計算會先套用加乘：(站點賣價 × 加乘) ÷ (另一站點買價 × 加乘) − 1，最後轉為百分比。

建立連線並開始偵測價差

  1. 按交易對資訊區的 開始（舊版畫面稱「開始偵測價差」）。
  2. 在「連接中」視窗等待兩站點成功；需要時可按「取消連接」。失敗時程式會自動重試。
  3. 主畫面的買一／賣一價格、數量與溢價指數開始持續更新，即代表行情已就緒。
i
此步驟不會啟動自動下單。

它只設定行情訂閱、資費與倉位更新；真正下單仍需在策略區按「▶ 開始」。

⚠
修改交易所或交易對後，必須再按一次「開始」。

既有行情連線不會自動切換到新設定；請等待兩個交易所重新連接成功後再啟動策略。

Direction

策略方向

預設為一多一空對沖。請用實際交易對與倉位頁再次核對方向，不要只依策略編號判斷。

i
紅色外框與 ✓ 是資費方向提示。

系統比較兩邊目前資費，標示較適合的策略方向；此提示不比較資費週期，也不會自動啟動策略，仍需自行判斷結算時間與風險。

Parameters

策略參數說明

策略1、策略2各自保存一組參數
畫面欄位意義輸入限制／判斷方式
下單數量（左格）交易所 1 每次下單數量。必須大於 0，單位依該交易所商品規格。
下單數量（右格）交易所 2 每次下單數量。必須大於 0；可與左格不同，用來對齊兩站點合約單位。
下單次數此輪策略最多成功下單幾組。正整數；達上限後策略停止。
掛單簿最低兩邊在符合價差的價位上，至少要有多少可用深度。必須大於 0；增強模式最多分析前 5 檔。
價差閥值允許進場的價差上限，單位為百分比。當前價差 小於或等於此值才符合。例：門檻 −0.10%，當前 −0.15% 符合；−0.05% 不符合。

數量不是金額。

Live trading

開始、更新與停止下單

啟動策略

  1. 確認行情價格仍持續變動，兩邊倉位與 API 名稱正確。
  2. 完整填寫該策略的兩個下單數量、次數、掛單簿最低、價差閥值與間隔。
  3. 按該策略的 ▶ 開始。
  4. 系統會驗證欄位與交易所連線；全部通過後顯示確認視窗。
  5. 重新閱讀「策略1／2所有參數設置正確」後才按「是」。按鈕變成紅色 ■ 停止 即代表策略正在監控下單條件。
  6. 每次啟動都會把該策略的下單次數重設為 0；停止後再次啟動也會重新計算。

執行中更新

允許修改下單數量、掛單簿最低、價差閥值與下單間隔後按「更新」套用。交易所、交易對、下單次數與加乘在執行中會被鎖定或不應變更。

停止策略

按紅色 ■ 停止 即停止後續送單。停止不會自動平掉既有倉位，請用「倉位」或交易所網站核對。

!
錯誤訊息出現後仍要人工查倉。

單邊明確失敗時，系統會停止策略並觸發查倉，最多留下當次一單未對沖，不會繼續下單累加；交易所回報仍可能延遲，請直接登入兩邊交易所確認訂單與曝險。

Schedule

預定時間

  1. 在策略下方輸入 24 小時制時間，格式必須是 HH:mm:ss，例如 23:59:30。
  2. 選擇「開始」或「停止」。
  3. 按「設定」後，狀態會顯示「預定開始@時間」或「預定停止@時間」；按「取消」可撤銷。
  4. 時間到達且動作完成後，排程會自動清除。
!
預定「開始」會略過人工確認視窗。

設定前先手動完成行情連線與參數核對。程式必須保持開啟，系統時鐘也必須正確。

Troubleshooting

常見問題排除

選完交易所後，API 名稱不正確或連線失敗
  1. 到「功能 → 系統設定」確認選到的交易所分頁與 API Key。
  2. 檢查 API 權限、Passphrase、IP 白名單、系統時間與網路。
  3. 儲存後停止策略並重啟程式，再重新選擇交易所。
按交易對資訊的「開始」後一直沒有價格
  1. 確認兩個交易對不是空白，且是各交易所實際使用的商品代碼。
  2. 查看連接視窗中是哪一個交易所失敗；取消後再試一次。
  3. 若剛切換交易所，請重新按交易對資訊區的「開始」建立連線。
  4. 確認防火牆、VPN 或公司網路沒有阻擋交易所 WebSocket。
策略「▶ 開始」沒有啟動

依錯誤視窗逐項補齊：兩個下單數量、正整數下單次數、掛單簿最低、價差閥值、正數間隔、交易對與交易所連線。

倉位顯示 N/A

N/A 可能代表沒有倉位、資料尚未回來、交易對不符或 API 沒有查倉權限。等候下一次更新後仍未恢復，請按「倉位」並直接到交易所核對。

一邊成功、一邊失敗或顯示下單逾時

立即停止兩個策略，不要直接重按開始。分別查看兩邊的未成交委託、成交紀錄與倉位，先處理單邊曝險，再檢查餘額、最小數量、Reduce Only、槓桿模式與連線狀態。

記憶體顯示紅色

通常不需要操作，Java 會自動清理記憶體。若使用量長時間持續上升且介面明顯變慢，可安全結束程式後重啟，並保留 logs/dualarbx.log 供排查。

Finish safely

安全結束程式

  1. 停止策略1、2

    所有紅色「■ 停止」都要恢復為「▶ 開始」。

  2. 確認沒有待處理訂單

    到兩個交易所查看未成交委託、成交紀錄與實際倉位。

  3. 記錄異常

    若發生拒單、逾時或單邊成交，保留時間、畫面與日誌。

  4. 關閉程式

    使用「檔案 → 退出」或關閉視窗；程式會停止背景更新任務並結束。

⚠
關閉 DualArbX 不等於平倉。

程式退出只停止後續自動操作，交易所上的倉位與未成交委託仍由交易所管理。
